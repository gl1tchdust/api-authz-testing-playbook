# Property names worth trying in a mass-assignment probe.
#
# Ordered by what they change, not alphabetically. Names that flip an
# authorization decision come first, because those are the ones that turn a
# shrug into a finding.
#
# How to use this:
#
#   One name per request. Adding several at once makes it unclear which was
#   accepted, and some frameworks reject an entire body on a single unknown
#   property, which reads as "not vulnerable" when it is not.
#
#   Try each in camelCase, snake_case and PascalCase. Only the convention the
#   server's model actually uses will bind. Both spellings of the common ones
#   are listed; derive the rest.
#
#   Always read the object back. A 2xx on the write proves nothing.
#   See cases/API3-MA-01 for why.
#
# This list is deliberately short. A 10,000-entry list of every field name in
# existence costs more requests than it is worth; these are the ones that
# carry privilege.
